# Optional native PESTO implementation

Verified 2026-10-26. `neural/` builds the separate **MIR2Neural** extension and
its **PitchPESTO** class. The base MIR2 build and its 135 classes require no
neural dependencies. This is a usable local experimental implementation, not a
claim of production qualification or general recognition accuracy.

## Source and model contract

The port follows [Sony CSL Paris PESTO](https://github.com/SonyCSLParis/pesto/tree/62bc0c9702558f19af4593752947fb9db1eadac9)
at revision `62bc0c9702558f19af4593752947fb9db1eadac9`, with the `mir-1k_g7`
checkpoint trained on MIR-1K. The checkpoint SHA-256 is
`16c32e06ddd950e3e4866dfa3c7f8a87c4988f8adf43e57977b189f031f26f3e`.
See [the v2 paper](https://arxiv.org/html/2508.01488v1), the
[candidate audit](neural-pitch-research.md), and
[license notices](../neural/THIRD_PARTY_NOTICES.md).

The pinned package metadata explicitly includes the weights and identifies the
package as LGPLv3. That is stronger scope evidence than repository placement
alone; no separate checkpoint-specific grant was found. This implementation
ships source and native binaries without weights. Local export is explicit;
weight redistribution remains a separately recorded release question.

The offline exporter checks SHA-256 hashes of the checkpoint and executable
upstream modules before importing/loading them. NumPy 1.26.4, SciPy 1.13.1,
PyTorch/Torchaudio 2.2.2 form the recorded reference environment. Python and these
packages are absent from server runtime. There is no ONNX backend, GPU
requirement, inference service or implicit download.

The model pack contains a versioned 32-float header, 130,575 network/confidence
parameters including the pitch shift, 251 bounded kernel descriptors, and exact
float32 frontend coefficients. `model.wav` is a float32 data container for
explicit `Buffer.read`, not playable audio. `model.f32` serves the native probes.
The manifest pins generated bytes, dimensions, preprocessing, source and package
versions. Packs are generated separately for 16/44.1/48/96 kHz; the UGen rejects
mismatched rates, malformed sizes/offsets and non-finite model data.

## Preserved behavior

- 251 VQT bins, three bins per semitone, `fmin=27.5`, centered bins, `gamma=7`,
  one harmonic and a 10 ms hop. The original generator supplies window placement,
  imaginary sign, periodic Hann coefficients, normalization and square-root lengths.
- Streaming mode `mirror=0`: trailing windows with zero initial history. In the
  pinned implementation, `mirror=1` adds right-side zeros; it is not the paper's
  refill mode. No refill or extrapolation is claimed here.
- Cropping `[16:-16]` leaves 219 encoder inputs. The original in-place operation
  means the network receives **natural log-power**, rather than its earlier dB
  tensor. LayerNorm epsilon, three 39-bin prefilter stages, two residual branches,
  LeakyReLU slope 0.3, pointwise convolutions and channel-major flattening are retained.
- The Toeplitz layer produces 384 softmax activations. The checkpoint's rounded
  offset rolls them by −20 bins. Argmax-local averaging uses offsets −2…2 and
  repeats boundary bins after clamping, as the original decoder does.
- Confidence uses all 251 energy bins, a learned stride-three convolution,
  spectral flatness and a learned sigmoid classifier. It is distinct from pitch
  correctness. The UGen separately gates frequency using confidence and a tiny
  energy floor; raw reference outputs are compared before this application gate.

The native frontend uses compact nonzero taps. Network convolutions keep blocks
of output accumulators in registers; Toeplitz outputs are also vectorized across
independent rows. Each row retains its accumulation order. No external numerical
runtime or architecture-specific instruction set is required by the source.

## Scheduling, memory and latency

A completed trailing window is frozen at each hop. Its frontend and network work
are distributed over the following hop; results publish at the next hop boundary
and are held between updates. A measured frontend cost weight prevents its slower
dot products from concentrating at the beginning of the hop. Publication is
independent of how the input is divided into server blocks.

The CPU loop allocates nothing, opens no files, starts no threads and reads no
clock. A Synth allocates 256,008 bytes of native state in the tested x64 build.
Model data are shared in an immutable global Buffer; the plugin holds the server's
required shared buffer lock while reading. It detects changed/freed storage and
fails silent. In-place model editing is outside the contract: stop all users,
wait for `s.sync`, then replace/free the Buffer. Constructor validation and state
initialization are separate startup work; create analyzers before a timing-critical
passage.

| Rate | Window | Model buffer bytes | Center lag including pipeline | Warmup before published full-history result |
|---|---:|---:|---:|---:|
| 16 kHz | 4096 | 2,967,792 | 138 ms | 270 ms |
| 44.1 kHz | 8192 | 7,255,336 | 102.88 ms | 200 ms |
| 48 kHz | 8192 | 7,850,408 | 95.33 ms | 190 ms |
| 96 kHz | 16384 | 15,174,424 | 95.33 ms | 190 ms |

Control-block quantization adds up to one block. Center lag describes window
position; it is not a guarantee of note-change settling time. Standalone cached
file loading plus model validation/state setup took 2.31–2.47, 5.94–6.34,
6.38–6.82 and 12.30–13.23 ms respectively. Those measurements include file I/O in
the probe; the UGen reads the already loaded Buffer instead.

## Numerical evidence and accuracy limits

Eight deterministic fixtures per rate cover silence, 110/440 Hz tones, harmonic
pitch steps, seeded noise, chirp, quiet tone and amplitude steps: **1,800 frames**
from independently executed original streaming inference. All arrays are checked
for nonempty expected shapes, finite data and complete frame counts. Reference
hashes are checked before comparison.

Maximum native/reference differences across these fixtures:

| Measure | Observed maximum | Acceptance bound |
|---|---:|---:|
| Pitch | 0.05150 cents | 0.1 cents |
| Confidence | 6.08e-6 | 1e-4 |
| Summed energy, relative | 6.24e-6 | 1e-4 |
| Frontend power relative to frame peak | 1.05e-5 | 1e-4 |
| Pitch posterior, absolute | 0.001528 | 0.002 |

Float32 cancellation in almost empty VQT bins can produce larger log-domain
errors: the reported maximum is 1.118 natural-log-power units. An initial 1e-4
posterior tolerance failed. Isolating the encoder on identical reference features
reduced its posterior error below 3.8e-5 and pitch error below 0.0023 cents. The
end-to-end tolerance therefore records this frontend rounding effect explicitly;
it is not described as bitwise framework equivalence.

The scheduled and unscheduled native paths are **bit-identical** for all 1,800
frames at each of the 32/64/128-sample block sizes. Source timestamps and the
additional one-hop delay are verified, including hops that do not divide the
server block size.

These are port-correctness fixtures. They are not an annotated voice/instrument
corpus benchmark. For example, the original model's 110 Hz sine estimate can
settle near 112.14 Hz (about 33 cents sharp); preserving that output does not make
it correct. Broader recognition quality and confidence calibration remain open.

## Timing evidence

Intel Core i5-10600K at 4.10 GHz, macOS 15.7.2 x86_64, AppleClang 17, Release
`-O3`, without fast-math. Sequential standalone probes use the same streaming
engine as the plugin. Ten initial frames per fixture are excluded from warmed
statistics. Whole-hop median times are 1.99/2.50/2.57/3.54 ms at the four rates;
putting that work in a single small audio callback would miss its deadline.

Selected scheduled results, in microseconds:

| Rate / block | Blocks | Median | p95 | p99 | Maximum | Deadline | Misses |
|---|---:|---:|---:|---:|---:|---:|---:|
| 16 kHz / 64 | 925 | 797 | 903 | 971 | 1084 | 4000 | 0 |
| 44.1 kHz / 32 | 5097 | 165 | 259 | 300 | 484 | 726 | 0 |
| 48 kHz / 64 | 2775 | 322 | 422 | 482 | 649 | 1333 | 0 |
| 96 kHz / 64 | 5550 | 239 | 352 | 358 | 693 | 667 | 1 |
| 96 kHz / 128 | 2775 | 476 | 594 | 614 | 732 | 1333 | 0 |

Across all 12 rate/block combinations there was one observed deadline overrun
in 41,300 measured blocks. **Prefer 128-sample blocks at 96 kHz.** This is observed
single-instance timing, not a hard real-time guarantee or a polyphony budget.
Other graphs, hardware, OS scheduling, model initialization and shared buffers
can change the available margin. All combinations and hashes are recorded in
[the measurements JSON](neural-pitch-measurements.json); timing failures are
reported separately from the numerical pass flag.

## Installed verification and build scope

- Strict native macOS x64 scsynth and supernova builds; three native CTests pass.
- Three AddressSanitizer/UndefinedBehaviorSanitizer tests pass, including buffer
  bounds, finite arithmetic and arbitrary input-block partitioning. A complete
  50-frame 96 kHz sine fixture also passes through the sanitized streaming probe
  with the real exported model. Debug/sanitizer timing is excluded from performance claims.
- Strict Windows x64 MinGW cross-build, with only Windows system runtime imports;
  this is not native Windows execution.
- Installed NRT contract checks at 16 kHz/64, 44.1 kHz/32, 48 kHz/64 and 96 kHz/128,
  plus supernova at 48 kHz/64: 440 Hz, learned confidence, silence, warmup,
  malformed model and freeing a model while its Synth remains alive.
- The **actual help example** is extracted and rendered for all five profiles.
  Both original and pitch-controlled synthesized voices are audible; outputs
  remain finite. The raw analysis channels are monitored before smoothing.
- Forced `SCDoc.indexAllDocuments(true)` and rendering of `PitchPESTO` plus the
  shared MIR2 guide complete without warnings or errors.

The local extension and explicitly generated models are installed for immediate
use after class-library recompilation. The CI definition adds model-free native
builds/tests for macOS x64/arm64, Linux x64/arm64 and Windows x64, plus sanitizers;
it has not been run on hosted runners. No artifact or source has been published.

Remaining qualification includes native non-x64-macOS execution, longer live-server
endurance and polyphony tests, recording-based accuracy, and model redistribution
terms before any weight bundle. Other audited neural candidates remain unimplemented.

## Short live-server checks

Additional muted CoreAudio runs use 48 kHz, 64-sample server blocks and a
256-sample hardware buffer on the same host. Each backend records 60 seconds of
sampled phases, plus separate warmup and 64 Synth construction/destruction cycles.
Single and two-analyzer phases each last 20 seconds. A further 10-second phase
silences only the second input to check independent state while sharing one
read-only model Buffer. Supernova uses a `ParGroup`; scsynth uses a normal Group.

| Backend / phase | Mean reported CPU | Maximum reported peak CPU |
|---|---:|---:|
| scsynth, one analyzer | 27.54% | 44.76% |
| scsynth, two sharing a model | 53.52% | 79.84% |
| supernova, one analyzer | 27.48% | 29.58% |
| supernova, two sharing a model in parallel | 32.69% | 35.01% |

Both servers returned 800 monitored analysis replies at 10 Hz with no invalid
value, pitch or voicing result. The 440 Hz input's maximum reported frequency
error was zero; the second analyzer correctly became unvoiced while the first
continued tracking. All 64 lifecycle iterations completed, no Synth remained,
and reported idle CPU returned near its initial baseline. These are lifecycle
checks, not a general heap-leak proof. No audio-underrun or late-processing
message was observed in these short runs.

The host logs also contain VSTPlugin duplicate Objective-C class messages;
supernova printed duplicate default-group IDs during startup. The measured
private analysis nodes initialized and completed successfully. These environment
messages are retained in the local logs rather than treated as plugin failures
or silently removed.

CPU figures are server status samples every 0.5 seconds; they are not individual
callback timings, and initialization/churn is excluded from steady statistics.
They establish these two small local graphs, not arbitrary polyphony or long
session stability. [The live measurements](neural-pitch-live-measurements.json)
include phase lengths, ranges and hashes of the full local CSVs/logs.

## Reproduction

See the [extension README](../neural/README.md) for build and explicit model
export. Generate fixtures for all four sample rates into separate
`export-16000`, `export-44100`, `export-48000`, `export-96000` folders, then run:

```sh
python neural/tools/check_parity.py \
  --probe /path/to/build/pesto_probe \
  --stream-probe /path/to/build/pesto_stream_probe \
  --exports /path/to/reference-exports --output /path/to/new-results
python neural/tests/run_server_checks.py \
  --sclang /path/to/sclang --exports /path/to/reference-exports \
  --output /path/to/new-server-results
```

The second command requires the optional extension already installed. All tools
refuse to overwrite existing result directories/files. Generated weights, audio
and full traces belong in ignored build directories, never source commits.

Run the muted live check separately for each backend, with a free local port:

```sh
sclang -D neural/tests/sc/live_runtime.scd \
  /path/to/export-48000/model.wav /path/to/new-live.csv scsynth 57181
```

Use `supernova` and a different CSV/port for the parallel-group case. This script
boots and quits its own server; it requires a working 48 kHz audio device.
